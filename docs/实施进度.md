## 二·七、Windows GBK 编码加固（第 7 轮，2026-10-25 晚；37 实机部署问题修复）

**问题（37 Windows 实机部署暴露）**：`.venv\Scripts\pip.exe install -r requirements.txt` 抛 `UnicodeDecodeError: 'gbk' codec can't decode byte 0x80`。根因实测确认：pip 的 `auto_decode` 对无 BOM 文本文件按系统 locale 解码（中文 Windows = GBK），而仓库 `requirements.txt` 是 UTF-8 无 BOM 且注释含中文（190 字节、51 个非 ASCII 字节，崩在「送/调」等字的 UTF-8 连续字节）——沙箱本地 `data.decode('gbk')` 同款复现。

**修复（三层防御 + 举一反三）**：

1. `requirements.txt` 注释改纯 ASCII（197 字节、0 非 ASCII，任何 locale 的 pip 均可读，根除该问题类别）。
2. `deploy/scripts/` 两个 Windows 启动脚本头部设 `PYTHONUTF8=1`（.bat 用 `set`、.ps1 用 `$env:`）——整个子进程树（app 及其插件子进程）统一 UTF-8 模式。
3. 全局编码加固（AST 扫描 app/scripts/plugins/tests 全部文件 IO 与管道）：

**背景**：37 Windows 实机部署后反馈四个问题（20:11 群消息）：①启动 Hindsight/SnowLuma 后刷新页面变回「已停止」、启动按钮仍可点；②日志端点只回一小段，拿不到 SnowLuma WebUI 登录令牌；③下载/更新无进度反馈；④需要 LLM/人设设置页。本轮后端全修（前端 V5 由设计匠人并行开发，未动 console/ 与 shared/qq-agent-console）。

### A. 状态失真根治（问题①）

1. **根因**：`_pid_alive` 只认 `/proc`——Windows 恒判死，monitor 循环 10 秒内把 running 误翻 stopped（前端 1.2s 轮询立即显示，37 看到的就是「刷新即回跳」）。
2. **平台感知探测**：Windows 走 ctypes `OpenProcess(PROCESS_QUERY_LIMITED_INFORMATION)`+`GetExitCodeProcess`（微秒级、无子进程；附 `GetProcessTimes` 创建时间比对 started_at 做 pid 复用防护）→ tasklist `/FI PID eq` 兜底；macOS/BSD 无 /proc 退 `os.kill(pid, 0)`；POSIX 保留 /proc。
3. **句柄优先原则**：spawn 进程句柄 poll 恒准恒优先（`_monitor_once` 中句柄活着就不做 pid 兜底探测——探测失真不再误杀 running）；句柄丢失（服务重启）才退平台 pid 探测，`_load_state` 探活保 running（跨刷新/跨服务重启稳定）。
4. **docker 形态容器口径**：monitor 新增 `docker inspect -f {{.State.Running}}` 容器真实状态（running/stopped 为准；http 探测只补 detail——容器在跑而 REST 未就绪是「启动中」不是「已停止」，正好治 37 的 Hindsight 回跳）；本机无 docker（inspect 无信号）时沿用 http 权威口径（远程部署形态）；**修隐藏 bug**：旧逻辑 http 探测失败会把 installed 误翻 stopped（未启动≠已停止），现仅 running 可降级。
5. **重复 start 明确拒绝**：句柄活/pid 探测活/容器 running 时 `start()` 返回 `ok=False + running=True + error`（旧口径 ok=True+note 前端无法锁定按钮）；`start(force=)` 供 update「停旧装新自动拉起」路径绕过。
6. **秒退探测**：spawn 后 1.5s 观察窗，立即退出则返回 `exit_code + log_tail（stderr 尾部）+ hint 修复指引`并留痕日志，不再「启动成功→10 秒后谜之回跳」。
